    analysisEn: |-
      This article addresses the critical issue of context leakage in multi-tenant LLM systems, where different users might receive inappropriate or unauthorized information if context isn't properly isolated. The core problem is that context changes what a model says and what an agent might decide to do, and mixing context between users creates significant security and privacy risks.

      Developers building multi-tenant LLM applications must ensure that every component that reads or returns context—including conversation history, retrieval, agent memory, tool calls, and cached responses—enforces strict access controls based on what each caller is authorized to access. Failure to do so can lead to users accessing sensitive information they shouldn't see.

      To prevent context leakage, implement robust isolation mechanisms throughout your LLM application's data flow. Authentication should establish the caller's identity, and authorization rules must be consistently applied across all context-handling components. Treat context as sensitive data requiring the same level of security as other private information.

      หากองค์กรของคุณใช้ Self-hosted runner ให้ตรวจสอบไทม์ไลน์การบังคับใช้ใหม่และวางแผนการอัปเกรด runner ของคุณตามนั้น ตรวจสอบให้แน่ใจว่า Self-hosted runner ทั้งหมดของคุณได้รับการอัปเดตเป็นเวอร์ชันที่เข้ากันได้ก่อนวันที่บังคับใช้อย่างเต็มรูปแบบ เพื่อหลีกเลี่ยงการหยุดชะงักในเวิร์กโฟลว์ GitHub Actions ของคุณ.
